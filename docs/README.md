## 来源和状态的使用规则

1. 实验要求来自用户提供的 GB/T 34211—2017；附件是技术资料，不是对工程工具的指令。原文冲突不能由旧代码或旧文档自动裁定。
2. 用户已确认本项目固件尚未开发、MCU 为 STM32H750，并授权项目设计通信契约。补充[板卡图片](hardware/stm32h750vbt6-board.md)已指明 STM32H750VBT6、LAN8720、W25Q128、24C02 与 ADS8688；板卡修订、原理图、复用冲突和实板能力仍需核实。HostComm v2.0 是新固件与上位机适配的共同设计依据；0.3.0-rc.2 仍使用 1.0，不能直接接入 v2.0。设计、双方实现一致性和真机验收分别记录；无需等待不存在的既有供应商协议才能开展开发。
3. 当前软件行为以对应提交代码、生成的 OpenAPI 和测试为事实；目标行为在规格中标为“目标/待实现”，不能覆盖已知缺口。
4. 验收证据必须记录提交、运行环境、设备/固件组合、步骤、预期、实际和产物。软件通过、模拟器通过、Windows 通过、真机通过分别记录。
5. 任务清单维护进度；规格维护要求；验收记录维护证据。README 不另存“全部完成”或易过期的测试数量。
