# ADR-001：用受限 JWT 完成默认口令强制修改

## 状态

已接受

## 日期

2026-08-30

## 背景

系统首次生产启动会创建 `admin`，一次性随机口令由安装器生成。仅显示修改提示不能阻止初始口令长期留存，也不能阻止该账户在改密前调用业务 API 或建立实时 WebSocket。

## 决策

- 用户表保存 `must_change_password` 持久标记；新建用户、管理员重置密码及默认管理员均置为 `1`。
- 登录响应和签名 JWT 以新增的可选布尔字段携带该状态，保持旧客户端与旧令牌兼容。
- 标记为真时，仅允许查询本人、登出和修改本人密码；实时 WebSocket 直接拒绝连接。
- 改密成功后清除数据库标记、写入操作审计，并要求客户端丢弃旧令牌重新登录。
- 数据库升级时将已有的 `admin` 账户标记为必须改密，确保旧安装不会绕过新策略。

## 备选方案

### 仅在前端跳转改密页

不能阻止直接调用 API 或 WebSocket，拒绝采用。

### 每个受保护请求都查询数据库

状态始终最新，但会给全部 API 增加数据库访问；当前单机 HMI 通过短期 JWT 和改密后重新登录满足要求，暂不采用。

### 默认生成随机密码

需要新增安全分发和找回流程，不适合当前离线部署方式，暂不采用。

## 后果

- 登录响应新增 `must_change_password`，未识别该字段的客户端仍可解析原有字段。
- 改密前的令牌权限被严格限制；改密后必须重新登录取得正常令牌。
- 旧安装升级后，用户名为 `admin` 的账户会执行一次强制密码轮换，即使此前已自行修改过密码。
