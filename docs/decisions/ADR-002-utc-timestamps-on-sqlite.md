# ADR-002：SQLite 时间戳使用规范化 UTC ISO 文本

## 状态

已接受

## 日期

2026-08-30

## 背景

历史实现使用运行机器的本地时区生成 ISO 8601 字符串。不同偏移的字符串不能可靠地按字典序比较，工控机时区配置变化也会改变新数据的语义。

## 决策

- 所有业务时间戳统一为秒精度 `YYYY-MM-DDTHH:MM:SS+00:00`。
- 使用 SQLAlchemy `UTCISOText` 领域类型，在 ORM 写入和读取边界执行格式校验与 UTC 归一化。
- 无时区的历史值按 UTC 解释；带偏移值换算为 UTC。
- Alembic 数据迁移用 SQLite `strftime` 一次性归一化所有已有时间列。
- API 查询边界接受标准 ISO 8601 偏移并先换算为 UTC；前端统一转换为浏览器本地时间展示。

## 备选方案

### `DateTime(timezone=True)`

本项目使用 SQLite。实测 SQLAlchemy 的 SQLite 方言写入带时区 `datetime` 后读回为无 `tzinfo` 的对象，无法满足“时区语义不可丢失”的要求，因此不采用。

### 保存 Unix 时间戳

数值比较可靠，但会破坏现有 REST、CSV、报告和 HostComm 的 ISO 8601 契约，迁移成本与可读性损失较高，暂不采用。

## 后果

- 相同格式的 UTC 文本可以可靠地使用现有索引排序和比较。
- 旧的无偏移时间会被解释为 UTC；无法从这类历史值恢复原机器本地时区。
- 数据库物理列仍是 SQLite `TEXT`，但应用层不再允许未经校验的任意时间字符串。
