# ADR-003：统一文档与主干基线，保留有价值历史

## 状态与日期

已接受，2026-09-05。按用户授权实施；进度见任务清单。

## 背景

`main@ac39ce5` 落后于 `dev@855c84d` 64 个提交。`feat/ui-refresh@fbb57df` 在 dev 上有 3 个独有提交；`release/commercial-readiness@e80d885` 与 dev 文件树相同。旧文档同时规定只用 main、持续使用 dev，以及两种合并策略，且将软件候选错误描述为只剩真机验收。

## 决策

- 文档入口放在 `docs/README.md`，工程规则放在根 `AGENTS.md`，CLAUDE 保留引用桥接。
- 需求、代码现状和验收证据分开记录；任务进度只在任务清单更新。原型、旧阶段清单与旧规则进入有明确基线的历史档案。
- 整合前备份全部引用为仓库外 Git bundle，验证恢复与对象完整性，并记录引用清单。
- dev 通过一次性保留祖先关系的 PR 合入 main；UI 3 个独有提交单独审查后 squash。重复分支和已吸收工作分支随后删除。
- 之后使用 main 与短期分支、PR squash、必要 CI 和合并后自动删分支。保留全部原主线历史及既有标签，不 force push，不移动标签。
- 继续以 `backend/app/__init__.py` 的版本为真源；包清单、前端版本与 tag 通过检查保持一致。

## 替代方案与后果

将 dev 全部 squash 会丢失此次希望保留的祖先关系；立即删除其他分支会丢失尚未审查的 UI 改动；全历史重写增加协作者恢复成本，因此均不采用。一次性整合之后再启用未来线性历史规则，不用未来策略否定已经存在的历史。

平台无法启用分支保护时记录实际限制，不能声称已强制保护或隐式购买计划。缺少软件证据和缺少真机证据分别登记。
