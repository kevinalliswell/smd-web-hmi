# ADR-006：候选实验契约、完整性与测定边界

## 状态与日期

已接受为软件实现约定，2026-09-06；尚未冻结为 STM32 交付协议。继承 [ADR-005](ADR-005-shared-runtime-and-evidence.md) 的单后台和板端执行边界。应用版本推进为 `0.3.0-rc.2`；实现与验证记录见[当前软件证据](../verification/2026-09-06-software.md)。

2026-09-06 后续决定：用户确认新固件尚未开发。[ADR-008](ADR-008-hostcomm-v2-design.md)建立由项目定义的 2.0 设计基线；本记录继续解释现有 1.0 软件约定，不能作为新固件实施接口。

## 背景

同一试验包含测定、撤 CO 与氮气冷却。命令受理、测定完成、设备安全终态和数据完整性是不同事实。仅靠状态名、收到的样本数量或网络在线，不能证明整次试验完成或首滴监测没有缺口。标准流程与受限非标配方还必须绑定同一份设备执行版本。

## 决策

1. 沿用 HostComm 1.0 帧，按握手能力分别启用 `recipe_v1`、`run_lifecycle_v1`、`measurement_events_v1`、`telemetry_sequence_v1`。详细字段和兼容策略集中在[候选扩展契约](../hostcomm-experiment-extensions.md)。没有能力声明时不猜测字段，不把 Mock 的声明当作供应商承诺。
2. 配方保存不可变版本和定义摘要。设备范围来自只读 `safety_profile`；激活经统一参数事务下发、CRC 和回读验证。启动前保存实际参数/配方快照，并向支持的设备发送 `expected_recipe` 身份，防止校验与执行使用不同版本。
3. 操作状态、实验阶段和数据质量分开存储。`accepted` 只表示命令被受理；停止受理只记录请求，继续采集。自动闭合需要匹配实验身份、能力声明、安全终态和有效料层温度低于 200 ℃。
4. 采样、遥测游标和生命周期边界在同一事务提交。保留设备原始时间、接收时间、boot_id/sequence 与异常证据；重复、乱序、重启、丢样或不支持证据时，不根据在线状态推定完整。
5. 原始采样持续到安全收尾；指标只使用测定窗口。测定结束时保存采样 ID 边界与测定完整性，后续冷却缺口可降低整次试验完整性，但不改写已有测定边界。缺失和损坏的元数据输出限制，不补造数值。
6. 有效首滴必须来自声明能力的有效布尔事件。无滴落的 1580 ℃替代值还需有效测定完成、监测和数据完整等证据。报告始终标记 `compliance=not_certified`；算法测试不构成国标符合性认证。
7. 未闭合、身份冲突等会话进入核查流程。管理员可在在线、新鲜、空闲且有效料温低于 200 ℃、明确现场确认后归档为 `archived_incomplete`；不得将人工归档提升为有效试验。元数据补录保留前后值、原因与操作者。

## 后果与未冻结项

旧固件仍可在既有权限/状态许可内联调，但记录为 `legacy_unverified`，不能执行选定的阶段配方或自动证明完整测定。不同能力可分别协商；缺少首滴或遥测能力会限制报告，不允许用重量阈值或主机时钟弥补证据。

设备日志补传、跨设备重启的操作去重/结果查询、真实质量字典、首滴检测器、气体标态与安全范围仍由 Q1—Q5/Q7/Q9/Q10/Q13/Q15 交付。Mock 只验证候选报文和软件路径；冻结须附真实固件版本/hash、黄金向量和异常实测。人工关闭不改变原始记录，后续报告保存新产物而不覆盖旧文件。
