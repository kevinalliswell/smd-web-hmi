# ADR-009：HostComm 2.0 上位机运行、源证据与双端交付

日期：2026-09-06。状态：接受；软件验证见[运行验证](../verification/2026-09-06-hostcomm-v2-runtime.md)，固件和现场验收另行记录。承接 [ADR-008](ADR-008-hostcomm-v2-design.md)，不改变 `2.0-design.1` 的报文语义。

2026-09-13 补充：[ADR-011](ADR-011-overwrite-install-and-software-release.md)更新覆盖安装的维护入口，并将软件正式版与指定设备组合资格分开；以下保留当时决策和验收范围。

## 决策

- 保留显式选择的 1.0 客户端，增加 2.0 适配器。新安装以未配对的 2.0 启动；升级保留原配置，不自动协商降级。缺少设备身份或 PSK 时仍能启动后台、登录和查询历史。
- Python 3.13 的 TLS 1.3 外部 PSK 用于生产设备连接；校验 AES-128-GCM、PSK 身份及无证书替代。客户端不缓存/传递 TLS session，不发行恢复票据。明文仅供显式启用、绑定回环地址的无执行器模拟器。
- HTTP 操作 ID 保留原 API 兼容性；持久 HTTP 报文 ID 与控制器 epoch 通过 UUID5 关联唯一板端操作。意图、固定报文 ID、uint64 字符串序号先落库，再发送。超时为未知，只查询或记录有依据的人工核查，不重放副作用。
- 内部租约使用原板端操作身份派生的独立 ID，前置命令未知同样可查询和核查。核查标记与执行结果分别持久保存；解除后续请求阻塞不等于原命令执行成功。已验证的历史配方不会因后来激活新版本而回退状态。
- 普通命令和停止分别占用维护锁与协议槽。停止使用当前认证会话已知的运行身份，由板端再次核对 boot/run；不因普通读取槽已满而失去停止通道。升级必须同时等待两类命令退出。
- 只有取得新鲜状态、工程配置与设备租约，才下发普通控制请求。连接和历史读取不抢占控制权；用户请求在后台取得板端租约，多个页面仍共享后台的操作者控制权与审计。
- 保存配方仍使用人类单位；编译产物使用协议规定的整数单位和单独摘要。不能精确表示的数值拒绝转换。旧版本和旧摘要不变；含糊的气氛阶段必须以新版本明确加热模式。工程配置只读，任何参数入口都不能覆盖它。
- 原始遥测/事件及补传分块先持久保存。ACK 只证明收到的字节已经入库；补传终态、摘要和区间校验通过后才投影为实验数据。重复来源按身份去重，冲突保留失败证据；补传不刷新实时控制状态。
- 源日志扫描水位与连续验证水位分开维护。确认无法取得的区间保留缺口并允许继续扫描后续记录，不把缺口自动算成完整；完成阶段自动补传，维护人员可显式重扫。
- `measurement_start/end/safe_boundary` 使用原始 boot/sample 引用。测定结束后继续保存置换、冷却；安全完成后结束档案，板端运行确认是独立动作。报告按原始序号而非数据库自增 ID 排序，首滴采用原事件温度。完整性由源样本和已验证日志区间推导，不能通过勾选或旧数据默认值获得。
- 数据库使用追加迁移 `hostcommv2001`。历史采样的新增字段保留 NULL；旧配方、旧实验、主线历史和标签不重写。

## 实现位置与验证边界

运行契约的 Python 类型位于 `backend/app/hostcomm/v2_contract/`，供后台和 PyInstaller 共用；`contracts/hostcomm/v2/` 的 Python 入口保留兼容导入，Schema、向量、C/JavaScript 检查入口保持原位置。

`V2Transport` 管连接与报文，`V2Client` 适配现有业务接口；操作协调、源日志、实验/报警投影分别维护。应用数据库中的写事务协调器服务于这些模块，不另建生产业务数据库。模拟器使用独立存储且禁止连接物理 I/O。

软件闭环以真实 TCP/TLS 模拟器、数据库、REST、浏览器和安装包 CI 为证据。模拟器的批准配置只对无执行器测试模型有效；STM32 固件、板卡接线/复用、传感器标定、CO/排风/急停联锁、国标争议批准、最高批准采样率 24h 和干净断网 Windows 现场验收仍是正式版前置条件。
