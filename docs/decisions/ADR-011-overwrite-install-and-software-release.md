# ADR-011：保留数据的覆盖安装与软件正式版

日期：2026-09-13。状态：已接受，实施与验收见[任务清单](../../tasks/todo.md)。本决策细化 ADR-005 的升级执行方式，替代 ADR-009/010 中“所有正式版本必须等待 M5”的发布范围规定；旧版行为与现场记录保留历史适用版本。

## 问题

rc.4/rc.5 要求用户先登录旧软件、输入目标版本并准备维护。设备离线时无法准备，卸载重装又可能遗留服务与持久数据。现场发生新版本与回退版本验活均失败后，旧版稍后恢复 ready，但事务仍处于 `rollback_failed`。恢复结果尚未取得，不能凭后续健康响应清除事务或推断失败原因。

## 决策

1. 日常更新只需运行新的安装器。安装器从已验证包清单识别目标版本，沿用登记的安装目录、数据目录和实际数据库路径，自动完成维护、停止服务、备份、迁移、切换和验活。设置页只展示“版本与维护状态”；旧 prepare/cancel/claim 网络入口退役并提供明确指引，设备源日志补传保留。
2. 新旧程序按版本隔离；数据库、账户、口令、配对密钥、配置、配方、实验与报告保留。新配置默认值不能覆盖已有值。支持同版本、相同发行清单修复；相同版本不同构建拒绝。普通降级拒绝，事务回退必须使用对应程序与数据库/配置快照。
3. Windows 管理员授权通过版本化、受 ACL 保护的本机请求/回执文件传递，不开新网络端口。请求绑定事务、操作类型、已安装版本、目标包摘要、管理员 SID 和物理停机确认。新后台在普通及优先命令锁内检查状态并回复；安装器确认 SCM 停止且实际进程退出后才能操作数据库。
4. 已知实验、加热、置换或冷却正在运行时拒绝维护，不代替操作员停止实验。已配对但离线或状态未知时，安装器允许 Windows 管理员确认设备已在现场安全停机后继续。确认只授权软件停机维护，不补写实验终态、不解除物理联锁、不恢复控制。未完成实验和未知操作仍须保留核查状态。
5. rc.4/rc.5 使用专门的安装器兼容路径：不伪造旧网页令牌或 JWT，不建立第二个设备网关。旧格式 prepared 文件仅阻断新命令；停止后重新核对持久活动记录。缺少可信实时证据视为未知，要求上述停机确认。升级、卸载、恢复、配对按明确操作类型执行，升级不能隐式继续未完成的卸载。
6. 完整程序仅暂存一次，位于安装盘；独立更新器引导程序从临时目录运行。验包后在同卷转正，避免同时保留两份完整解压载荷。解压前、停服务前以及停止后的数据库快照前分别检查相应空间；按卷累计暂存、备份、迁移/恢复临时空间，保留现有数据库最低空闲空间门槛，提前说明缺口。
7. 成功后程序版本保留当前、上一个可回退版本和未完成事务引用的版本。本次不自动删除数据库或配置备份，不清理原始数据与报告。卸载默认保留数据目录。
8. 新安装器识别旧失败事务，先额外保全当前数据库、配置和原始日志，经一次说明恢复影响后恢复一次，成功再继续更新。新事务持久记录“数据已恢复”“旧版已配置”“等待旧版验活”等阶段；只剩验活时不重复覆盖数据库。失败保留锁和证据，不盲目循环或通过删锁伪装成功。
9. `0.3.0` 的范围是软件正式版。必要软件检查、真实 Windows 安装升级及安装版 SmdBench 验收通过后，按同一提交和实际文件摘要发布。Windows Server CI 与 Win10/11 桌面人工验收分别记录；M5 仍是指定固件、硬件、安全联锁、国标实验及持续运行组合的资格门。软件稳定版本号不宣称设备已通过 M5。

## 验证与交付

稳定发布使用[机器证据契约](../release-acceptance.md)，拒绝只在 manifest 写 `passed`/`true` 的证明。必须验证实际安装器、联调工具 ZIP、工具清单、场景证据和日志字节，版本/提交/本次 CI 编号一致；旧 RC 标签和资产不变。未验收项随包公开。

正常覆盖安装、真实 rc.4/rc.5 数据升级、同版本修复、错误降级、离线确认、忙碌拒绝、旧事务恢复、自定义数据库与配置/账户保留必须有 Windows 执行证据。事务中断、迁移失败、低空间、并行安装、停止失败和完整回退保留故障测试。Win10/11 离线 WebView2、缩放、普通操作员、窗口关闭持续采集及真机验收各自保持未验收，直到对应环境证据取得。

## 后果

用户不再管理维护票据和目标版本；安装器承担状态判定、保全与恢复复杂度。Windows 管理员在未知状态下承担现场停机确认，审计必须可追溯。固定运行时和离线包继续由人工分发，不增加联网更新服务。
