# ADR-012：Tauri 桌面与分阶段业务现代化

日期：2026-10-22。状态：用户接受选型，实施及验收按任务逐项记录。

## 背景

现有 Vue/FastAPI/SQLAlchemy/SQLite、独立 Windows Service、唯一设备网关及事务安装链保留。用户确认采用 Tauri 2 + Vue 3/TypeScript + 独立 FastAPI 服务 + SQLite，先交付 Tauri 与新版实时总览，之后逐业务切片推进。参考 UI 只提供视觉依据，业务契约以仓库实现和批准规格为准。

## 决策

1. Tauri 为普通用户薄壳，加载受控配置中的本机同源页面；只允许预期 loopback 地址与导航。关闭、崩溃或重开窗口不控制服务，不创建第二设备连接。服务不可用时显示内置诊断页并允许重试；不自动改协议、进入 Mock 或降低证书校验。
2. Rust 不直接访问业务数据库、设备连接或现场密钥。原生能力按最小 capability 授权，外部来源无 IPC 权限。首批只实现必要窗口及诊断能力。
3. 共享 Vue 页面、API、认证和 WebSocket；增量迁移 TypeScript。现有 CSS token、Chart.js 及业务组件先保留，按交互需要采用 Reka UI，不同时全面更换 UI 和图表栈。
4. 后台仍是授权、状态和控制判断的执行方。STM32 执行实时流程，硬联锁拥有最终切断权。HostComm 1.0/2.0 显式配置，既有租约、未知结果、恢复、配方回读及受控停止语义不变。
5. 导出任务改为持久记录，并把渲染移出通信事件循环。独立有界 worker 只处理序列化快照；服务重启不自动重发设备操作或源日志扫描。公共任务接口和追加迁移在 P2 随实现验证。
6. 沿用 NSIS、Windows Service、ProgramData、配对及维护工具链。Tauri 最终保持 `SmdDesktop/SmdDesktop.exe` 路径和自检契约；不以独立 updater 替代整套维护事务。后端版本仍是应用版本真源。
7. Python 3.13、Node 24 为当前验证基线，Rust 锁定 1.95.0；依赖均按锁文件构建。Windows CI 构建实际安装样包，本机/Windows Server CI/Win10/11人工/真机证据分别记录。
8. P0—P7 使用独立分支和草稿 PR，不自动合并或发布。原始证据、已发布迁移、标签及历史验收保持可追溯。

## 迁移及退出条件

P1 的 Tauri 初次样包复用现有服务及前端，保留其余页面可用。旧 pywebview 壳先作为对照；只有新壳渲染、安装升级、证书、下载/打印、窗口关闭持续采集等验证完成后，才移除仅旧壳使用的依赖。Python 服务与维护工具不随旧壳删除。

升级保留自定义数据库、账户、配置、密钥和实验。若升级后已有新业务数据，禁止自动用旧备份覆盖。既有 ADR-011 维护事务和 FW/M5 验收边界继续有效。

## 验证和代价

引入 Rust/Windows 构建链、Tauri 来源限制和运行时验证；不能预设整体安装体积或内存一定下降。原版与新版使用同一隔离夹具比较启动、总内存、报告耗时和通信响应。所有完成声明必须有实际提交及产物。
