# HostComm v2 状态、停止与恢复

状态：通信语义设计基线；固件尚未实现，硬件动作与时序尚未验收。本文的“必须”约束 v2 实现，不能作为现有 HostComm 1.0 或 Mock 已支持的声明。报文字段、数值编码与资源上限以 v2 主契约和 Schema 为准。

## 身份与不变量

- `run_id` 是 32 位小写十六进制 UUID，由启动请求给定，在受理前持久化；同一运行跨 TCP 重连和板端重启保持不变，后续运行不得复用。
- `boot_id` 每次板端启动重新生成。`sample_seq` 仅由采样任务在本次启动内连续分配；状态查询引用已存在的采样，不制造新序号。
- `measurement_start`、`measurement_end`、`safe_boundary` 是可空的 `{boot_id, sample_seq}` 对象，sample_seq 为 uint64 十进制字符串。边界必须连同产生该样本的原始 `boot_id` 持久化；不能用重启后快照的 boot_id 解释旧序号。未知边界为 null。
- 测定窗口、原始样本、运行身份、配方摘要、安全配置摘要、阶段转换和停止原因必须可对账。先持久保存边界样本及运行记录，再宣告相应完成；持久化失败不得补造完成证据。
- 运行期间配方和工程安全配置使用不可变快照。通信任务仅递交受限请求；实时任务与硬接线联锁保有执行和最终切断权。
- 上位机归档不是设备状态转换。关闭窗口、退出登录、导出报告或补传历史记录，均不得结束采集、切换板端阶段或恢复加热/CO。

## 状态枚举与转换

状态精确区分大小写，只使用下列小写枚举；不得将 1.0 的 End、Done、Standby 等别名带入 v2。

| 状态 | 进入条件与含义 | 允许的后继 |
|---|---|---|
| `booting` | 上电/复位后建立新 boot_id，校验持久记录和安全输入；禁止恢复加热/CO | `idle`、`safe_disposal`、`fault` |
| `idle` | 无未确认运行，工程配置有效且启动许可可评估；不表示自动取得启动许可 | `preparing`、`maintenance`、`fault` |
| `preparing` | 启动 accepted 已原子预约身份、配方和工程配置；流程任务应用前重查停止/租约，随后执行不可被省略的预检和保护程序 | `measuring`、`safe_disposal`、`fault` |
| `measuring` | 板端执行阶段配方并持续记录；转换条件来自新鲜且合格的测量 | `safe_disposal`、`fault` |
| `safe_disposal` | 已锁存停止/自然测定结束，执行工程批准的撤 CO、撤加热许可与保护置换 | `cooling`、`fault` |
| `cooling` | 置换前置条件已满足，继续保护、监测和记录，等待合格安全终态 | `completed`、`safe_disposal`、`fault` |
| `completed` | safe_complete 已有持久证据；运行仍保留，等待 ack_run | `idle`、`fault` |
| `fault` | 发生联锁、恢复证据不足或安全动作不能确认；持续执行仍可实施的安全处置 | `safe_disposal`、`cooling`、`completed`、`idle` |
| `maintenance` | 无未确认运行且满足维护安全条件；不能启动实验或由维护接口直控危险输出 | `idle`、`fault` |

`fault` 不暂停安全任务、报警或采样。由 fault 进入处置/冷却只允许继续安全处理；进入 completed 仍须完整安全终态证据；进入 idle 必须满足故障恢复条件，并在存在运行记录时完成 ack_run。网络恢复、报警确认、故障解除均不得跳回 preparing/measuring。

自然测定结束先提交最后一个测定样本和 `measurement_end`，再转 safe_disposal。停止、联锁、超时或重启导致提前离开 measuring 时，也记录实际测定截止边界及原因，但不得据此宣告自然完成。之后所有置换、冷却样本仍归属原 run_id；不延长测定窗口。

## 运行结果与安全终态

preparing/measuring 不得携带 safe_complete=true 或安全终态边界，不能同时宣告测定仍在进行和安全收尾完成。

运行结果不由状态名推导；`completed` 只说明安全收尾完成。

| outcome | 判定语义 |
|---|---|
| `pending` | 尚无已确定的测定结束结果，或恢复结果仍待对账 |
| `valid_candidate` | 自然完成规定测定阶段，板端未发现测定窗口损坏；仍须上位机核对完整性、算法和批准规则 |
| `aborted` | 操作者停止、租约丢失等原因在自然测定完成前中断实验 |
| `invalid` | 已知故障、数据损坏或重启使测定条件/连续性无法证明；不得提升为有效实验 |

valid_candidate 不等于国标符合性结论。若后来发现测定窗口内损坏，应保留原记录和新增判定证据，降低有效性；不得覆盖历史结果。测定边界之后发生的通信或冷却问题单独降低安全收尾/全程记录完整性，不能移动已证明的测定边界。

safe_complete 只能在工程批准的撤危险输出、置换、冷却及传感器质量条件全部满足后成立；有效料层温度必须严格低于工程安全阈值，该阈值不得高于 200 ℃。执行请求已发出不能代替阀门、流量或其他工程要求的反馈证据。源端将终态采样保存为 `safe_boundary` 后才能宣告安全完成。

`ack_run` 是受控确认：仅在 safe_complete 已证明、告警触发条件已消失、所需报警确认及工程故障复位均完成后接受，保留运行记录后返回 idle。它不得隐式确认报警、清除仍活跃的联锁、重置配方进度或恢复加热/CO。未运行过的启动故障仅按批准恢复程序回到 idle，不能伪造 run_id。

## 租约与安全停止

设备只授予一个当前写入租约，租约具有 fencing 标识，超时使用板端单调时钟。更新所有权必须使旧租约立即失效；普通可变请求在执行点重新检查租约、身份和预期状态。页面操作员之间的控制权转移不等同于板端租约转移。

本版固定采用“失去控制租约后安全处置”：运行中租约到期、连接终止导致租约失效或控制器失联时，板端自主进入 safe_disposal；已在安全处置/冷却时保持或收紧处置，不能恢复 measuring。idle/completed 无活动危险过程时保持安全状态并撤销写入许可。重连只允许重新认证、读取和对账，不能撤销已经锁存的停止决定。

`stop_run` 必须满足：

1. 来自已认证、已配对且具有 control 角色的控制器，明确指定当前活动 run_id 和预期 boot_id。身份不匹配拒绝，不能把旧实验的停止请求施加到新实验。
2. 无须当前写入租约或 state_revision；不得因遥测过期、普通命令排队或控制权由另一用户持有而阻止。接收后进入独立的安全请求通道，但不能绕过硬件联锁。
3. 持久存储健康时，先记录操作意图及命令序号防重放水位，再报告受理/应用；重复请求只维持既有安全处置，不能重置置换/冷却计时、推进实验或恢复输出。
4. 意图不能持久化时，仍立即实施能够完成的单向安全处置；结果报告 unknown，保持持久化故障证据并禁止新实验。不得因无法保存审计而等待普通写入锁，也不得谎报 applied。
5. `applied` 仅表示安全处置请求已锁存并进入板端处理；safe_complete 与终态反馈另行报告。任意 ACK 都不得让上位机停止原实验采样。

上述软件停止不替代硬接线急停。板端在无法验证远程请求身份时仍独立执行本地联锁、看门狗与失联策略；不接受匿名网络“急停”入口。

## 操作持久化与断电恢复

普通副作用命令必须具有控制器 epoch、递增命令序号、操作身份和请求摘要。设备持久保存防重放水位；同一身份不同摘要拒绝，已经越过的序号即使结果明细已回收也不得作为新请求执行。只允许查询 retained/expired/unknown 等真实结果，不允许由“没有查到”推导“未执行”。

受理前检查状态与配置，在动作前提交意图；start_run 在受理时就预约 run_id 并发布 preparing，使 stop_run 能取消尚未应用的启动；运行身份、配方切换和相关记录必须具有明确原子提交点。若复位落在执行器动作与结果记录之间，恢复为中断或 unknown；不能许诺跨断电物理动作恰好一次，也不能自动重发不确定请求。

上位机恢复时先建立新连接/会话，核对 device_id、boot_id、未闭合 run_id、活动配方、工程配置、操作水位和日志范围，再恢复显示与采集。现有运行缺少本机归档时建立待核查记录；不得从第一帧倒推完整起点或将当前 idle 解释为历史正常结束。

对账结束不要求把未知旧动作改判为成功或失败。确认当前安全条件并保存恢复审计后，可用新序号执行允许的恢复/确认命令；旧 unknown 保留在历史中。仍在执行的 accepted 操作和未确认运行关联结果不可回收，已安全对账的历史 unknown 不永久占用执行槽，防重放水位仍保留。

板端重启必须清除旧租约。若存在未闭合运行，保留 run_id 及已证明边界，以新的 boot_id 继续安全恢复记录，进入 safe_disposal 或 fault；不得自动接续配方、加热或 CO。若失电期间输出、气氛、温度或记录连续性缺乏证据，结果与安全状态保持未知/无效。当前冷态读数不能证明失电全过程安全。即使安全处置完成，也必须对账后显式 ack_run 才能允许下一次启动。

## 采样、事件与日志补传

- sample_seq 只标识本次启动内的采样。首滴必须记录持久事件及检测时刻的料层温度/质量和源样本引用，不能以重连后首次看到的锁存布尔值确定 Td。
- 事件的源顺序身份为 boot_id 与 event_seq 的组合，event_id 是完整 UUID；报警 occurrence 用 alarm_id/occurrence_seq 定位并引用原始事件；确认报警只改变业务确认记录，不能删除原始发生/恢复事件。
- 日志按 record_seq 对样本和事件统一排序；记录保留原始 boot/run 身份。分块 SHA-256 摘要针对主契约规定的原始字节，不得在 JSON 重新序列化后比较。
- 补传固定查询范围及源端高水位，公布最早/最新可读位置和明确的不可用区间。实时采样可以继续；慢客户端或日志传输不得堵塞安全请求、命令结果和报警处理。
- 上位机先将校验后的原始分块字节与字节偏移持久化，再确认分块；跨块尾部暂存，只有完整合法记录落盘后才推进记录水位，收到但未落盘不算完成。字节进展不代表全范围无缺口。重连从持久游标恢复，重复记录按源身份核对内容。
- 补传只能新增原始证据和重新计算完整性，不能使实时状态后退或触发设备操作。填满缺口必须验证全范围、边界和质量后才能提升完整性，并记录新判定；历史报告不得原位覆盖。
- 板端不得静默覆盖未确认的实验数据；启动前检查存储预算，运行中空间不足执行批准策略并报告缺口。操作/运行关键记录与采样存储必须有独立保留保障。

## 必须通过的行为验收

| 场景 | 可观察结果 |
|---|---|
| 启动 ACK 丢失后重复提交 | 同一 run_id 至多建立一个运行；返回既有记录或 unknown，不从头开始 |
| 去重明细回收后重放旧序号 | 不执行；返回结果不可用，防重放水位保持 |
| 配方切换与启动并发 | 启动只绑定一个已提交的配方/工程配置组合；冲突请求拒绝 |
| 控制权移交后旧连接继续写入 | 旧 fencing 标识拒绝；认证有效的 stop_run 仍可作用于其明确指定的活动运行 |
| 遥测过期、普通队列堵塞时停止 | 安全通道锁存停止；继续记录，不能把 ACK 当安全终态 |
| 意图存储故障时停止 | 仍执行安全处置，结果 unknown，拒绝新实验 |
| 测定中租约丢失 | 板端自主处置，结果 aborted；重连不自动恢复 |
| 冷却中租约丢失 | 继续/收紧安全处理；不移动既有测定边界 |
| 首滴发生时网络断开 | 后续读到原始事件时刻、源样本及质量，不能采用重连时温度 |
| 断线期间自然测定结束 | 恢复的 measurement_end 指向真实边界；冷却样本不进入测定指标 |
| 采样过程中反复 get_status | 返回已有源样本，查询不会造成采样序号缺口 |
| 重启发生在危险输出动作前后 | 新 boot_id、旧 run_id；无自动加热/CO恢复；结果无法证明时 unknown/invalid |
| 冷却传感器无效或安全反馈缺失 | safe_complete 不成立，ack_run 拒绝，保留故障和采样 |
| 补传重复/损坏/缺失块 | 原始内容可核对；游标不越过未证明缺口，实时状态不后退 |
| 活跃联锁被 ACK 或故障复位 | 活跃条件仍生效；不得清除后自动恢复实验 |

## 工程配置与交付边界

软件团队在本版确定状态、身份、防重放、租约、断线处置入口、日志和恢复语义。硬件/安全负责人仍须批准实际阀门失电位置、排风/气源联锁、MFC 标态与量程、传感器质量判据、撤 CO/氮气置换与冷却动作、反馈、延时、看门狗和存储能力。

缺少配置、配置未批准、配置校验失败或实际能力不满足安全处置要求时，必须禁止启动并允许诊断与可实施的安全操作；不能用 Mock 数值填补工程限制。通过契约测试仅证明协议行为，正式运行还需固件实现、具体工程配置和真机异常注入验收。
