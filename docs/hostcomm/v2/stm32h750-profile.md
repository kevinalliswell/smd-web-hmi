## 已确认的器件资料

本次核对 ST 官方 [DS12556 数据手册](https://www.st.com/resource/en/datasheet/stm32h750ib.pdf)，读取版本为 **Rev 8，January 2026，335 页**。它同时覆盖 STM32H750VB/ZB/IB/XB；使用该 URL 不表示用户选择了 IB 后缀。[ST 产品页](https://www.st.com/en/microcontrollers-microprocessors/stm32h750ib.html)仅用于官方资料交叉核对。

| 器件级事实 | 对本项目的约束 |
|---|---|
| 片内 Flash 为 128 Kbytes | 不能预设网络栈、TLS、控制逻辑、升级镜像及持久日志都能放入片内；须以实际链接 map 和存储分区证明 |
| RAM 总量约 1 Mbyte，分为 AXI SRAM、D2/D3 SRAM、ITCM/DTCM 和 backup SRAM 等区域 | 按模块、堆栈、DMA 缓冲及缓存属性分别预算，不能把总量当作连续且可被所有 DMA 访问的缓冲池 |
| 内置 Ethernet MAC 与专用 DMA，通过 MII/RMII 连接外部 PHY | 芯片有 MAC 不表示板卡已装 PHY；PHY 型号、地址、时钟、复位、接口和引脚由原理图确定 |
| 提供 Quad-SPI、FMC 和 SDMMC 外设 | 具备接口不表示板卡装有外部 NOR、RAM 或 SD 卡；容量、总线和引脚冲突必须核对实装 BOM |

上述器件能力来源：数据手册首页、表 1、§3.3.3、§3.15/3.16、§3.39、§3.42。页码分别见第 1、18—20、24、33、49—51 页。[DS12556 Rev 8](https://www.st.com/resource/en/datasheet/stm32h750ib.pdf)

表中右列是本项目据器件资源作出的工程要求，不是 ST 对本项目软件容量或板卡接线的证明。当前不指定 CPU 实际时钟，也不把 RAM 的易失内容当作断电后必然保留的操作记录。

## 程序与持久存储方案

先生成最小目标构建的链接 map，分别计量启动/恢复、驱动、网络/TLS、协议、工艺逻辑、只读数据与 RAM 峰值。不能通过减少审计、去掉持久高水位或静默降级明文来掩盖容量不足。

外部存储是否存在尚未知，FW-01 需要明确选择并验证以下用途，而不是先假定一张 SD 卡可以承担所有持久职责：

| 用途 | 方案评估与退出条件 |
|---|---|
| 程序与离线更新镜像 | 若实测无法在片内满足容量与恢复要求，评估实装外部 NOR 等介质；明确启动校验、镜像切换和恢复入口，另记具体启动/升级决策 |
| 控制器 epoch、命令高水位、未决操作、激活配方索引 | 在已验证介质上提供可检测半写、冗余提交与恢复的独立持久区；逐写点断电后仍能拒绝旧命令 |
| 配方暂存与有效配方 | 满足契约最大对象、暂存/有效版本隔离及原子提交；失败不覆盖上一有效版本 |
| 大量遥测与事件日志 | 按采样率、保留时间与写入寿命核算 NOR 或 SD 等介质；验证满盘、拔除/失效、日志轮转和补传过期范围 |

以上为待落实的存储设计要求，不声明控制板已配备 NOR 或 SD。结果缓存、遥测轮转不得回收高水位和未决操作；可移除日志介质故障不得让设备失去已承诺的防重放保证。

## STM32H750 目标验证门槛

1. **Flash/RAM**：保存发布配置的 map、每段大小和峰值堆栈记录；包括 TLS 握手、8192 字节应用帧、Base64 块、规范摘要、日志和最坏并发队列。
2. **Ethernet DMA 与缓存**：保存链接段、描述符/缓冲地址及 MPU/cache 策略；依据总线访问规则验证，覆盖反复收发、重连和存储 DMA 并发，不能只凭一次 ping 通过。
3. **持久性**：在选定介质上逐提交边界断电，覆盖错误校验、半写、空间耗尽、介质故障和更新失败；高水位、运行身份及安全恢复符合 v2.0。
4. **负载与安全**：在批准的采样率下测量 CPU、队列、命令延迟和安全任务时序；先完成台架，再做 24h 与实际联锁验收。

完成这些门槛后将具体资源上限写入设备 profile 和能力声明；在此之前，HostComm v2.0 的资源限制仍是协议设计上限，不能宣称 STM32H750 板卡已满足全部组合。
