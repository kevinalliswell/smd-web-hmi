## 2. 每条验收记录的格式

保存到`docs/verification/`，文件名以日期和任务ID命名；大体积运行日志/录像存CI artifact或受控交付目录，在记录中填URI、保留期限与SHA-256。

```yaml
requirement_ids: [STD-12, M3-02]
implementation_commit: <完整SHA>
validation_commit: <测试/脚本SHA，若不同>
application_version: <版本>
environment: <OS版本/架构、Python、Node、依赖锁hash>
level: software | simulator | windows | hardware
firmware: <版本和hash；不适用写not_applicable>
hardware: <板卡/仪表/MFC型号和校准记录；不适用写not_applicable>
setup: <前置配置、数据集hash、采样频率>
steps: <可重复步骤和故障注入点>
expected: <可测量预期>
actual: <实际结果和限制>
result: pass | fail | blocked | not_run
artifacts: <日志/截图/报告/CI链接与hash>
reviewer: <负责角色/签字人>
```

“代码存在”“测试编写完成”“CI通过”“Windows验证”“真机签字”分别表述，不能用空表格或勾选替代运行证据。数据集须独立人工核算，不从被测算法反推预期。

## 3. 必测场景

| 范围 | 场景与成功标准 |
|---|---|
| 控制 | 握手拒绝/版本不符不放行；过期/未知状态不启动/改参；重复提交不重复执行；结果丢失显示未知；参数回读冲突不显示成功 |
| 恢复 | 自然结束与stop后冷却仍正确归档；后台/板端重启、断线、乱序、重复和缺口可以对账；未知归属显式保留 |
| 故障 | 慢DB/慢WS、队列满、磁盘满、写入失败不阻塞回执、不静默丢报警；过期数据和存储退化可见 |
| 算法 | H600、符号方向、10%/40%/500Pa边界、无效标志、缺基准、无滴落/未完成区别、附录B所有分支和修约 |
| 配方 | 标准模板变更生成custom；范围/能力/联锁约束；原子部署与回读；运行快照不可变；版本/模式进入报告 |
| 双端 | 相同权限和实验结果；多开无第二网关；窗口关闭/退出继续采集；重连报警一致；报告三格式可下载 |
| 安装升级 | 干净断网Win10/11x64，无Python/Node；普通操作员、中文路径、重启、迁移失败、升级断电、完整环境恢复 |
| 持续运行 | 冻结的最高采样频率至少24h，记录资源曲线、队列/数据缺口/操作延迟；无无界增长与未解释丢失 |
| 真机 | 按Q13联锁设计注入急停、CO/排风/超温、断电等场景，由硬件/安全负责人判定；软件不能替代实物安全动作证据 |
