## 独立语义审查

按实际客户端、投影、操作服务、模型与配对工具核对 26 种消息、8 种命令及首次连接顺序。审查修正了以下容易误导固件实现的表述：

1. `error` 的字段为 `code/message/retryable`，不是 detail。
2. 无租约但其余条件满足时，主机投影可以标识可申请控制；普通写下发仍必须先取得并确认租约。投影字段不是新增线字段。
3. 普通响应无需另行 ACK，但 log_chunk 必须遵守单块 ACK 窗口；acquire 需要没有任何有效租约。
4. hello 能检查能力声明集合，不能证明能力真实实现；真实持久操作、配方和日志能力由分阶段验收证明。

同时修正现行入口中的 rc.5/doc.2/doc.3 混用，以及陌生运行待核查/回放仍被描述为待实现的问题。历史 ADR、候选版本和验收事实保持当时语境。

交付包从最终 PR 提交的全部受版本控制文件生成，保留目录结构，不打包本地工作目录、Git 历史或开发运行环境。包内 `HANDOFF-README.md` 为阅读入口；`SOURCE-MANIFEST.json` 登记源码 SHA、版本映射和逐文件摘要。摘要清单不递归包含自身，包外 ZIP SHA-256 校验整个包。

交付时另生成包外 `validation.json`，绑定准确提交、ZIP 名称/摘要，并记录以下实际解包检查结果；具体文件数及摘要以该记录为准：

- 每个源文件与该提交的 Git tree 路径/原字节一致；没有未跟踪配置、数据库、运行凭据或发行二进制。
- 解压后清单文件逐个校验 SHA-256，并检查无清单外文件。
- 不依赖 Git 枚举，检查解压 Markdown 的相对链接/锚点、板卡三幅附图及机器契约入口。
