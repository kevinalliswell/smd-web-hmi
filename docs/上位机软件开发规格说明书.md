## 1. 概述与范围

### 1.1 系统定位

smd-web-hmi 是一个**本地部署**的工业 Web 上位机，运行在炉旁工控机上，通过局域网以太网与 STM32 控制板通信。浏览器前端运行在同一工控机或同网段终端上。系统**不依赖互联网**，所有功能须在断网状态下正常运行。

### 1.2 通信拓扑

```
浏览器 (Vue3)
  │  HTTP REST  (axios, localhost:8000)
  │  WebSocket  (ws://localhost:8000/ws/realtime)
  ▼
FastAPI 后端 (localhost:8000)
  │  TCP 长连接  (asyncio, port 34211)
  │  UTF-8 JSON Lines，\n 帧分隔
  ▼
STM32 控制板 (192.168.1.x:34211)
  │
  ├── 控温仪 (RS485/Modbus)
  ├── N₂/CO MFC (RS485)
  ├── 电子天平 (RS232/RS485)
  ├── AI 模块 (压差/位移/料层温度)
  ├── DI/DO 模块
  └── 安全继电器 (硬接线)
```

### 1.3 角色定义

| 角色 | 权限范围 |
|---|---|
| Observer | 只读：查看实时数据、历史、报警 |
| Operator | Observer + 启动/停止/暂停/复位/确认报警/天平去皮 |
| Admin | Operator + 参数下发、校时、用户管理 |
| Maintainer | Admin + 设备诊断、HostComm 调试工具 |

## 3. 后端 API 设计（FastAPI）

所有路由前缀 `/api`，返回格式统一：

```json
// 成功
{"data": <payload>, "ts": "<ISO8601>"}
// 失败
{"error_code": "<CODE>", "message": "<说明>", "ts": "<ISO8601>"}
```

认证：除 `/api/auth/login` 和 `/api/system/health` 外，所有路由须携带 `Authorization: Bearer <token>`。

### 3.3 命令接口（`/api/commands`）

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| POST | `/api/commands` | Operator+ | 下发命令 |

请求体：

```json
{
  "command": "start_test",
  "params": { "test_id": "TEST-20260609-001" },
  "confirm_token": "uuid-二次确认令牌（可选）"
}
```

响应：

```json
{
  "data": {
    "msg_id": "pc-cmd-000001",
    "result": "accepted",
    "reason_code": "ok",
    "reason_text": "...",
    "current_state": "Precheck"
  }
}
```

**命令服务逻辑（`command_service.py`）：**

```
1. 解析当前用户角色 → 校验命令权限（见角色权限矩阵）
2. 读取内存缓存中当前状态 → 校验状态限制
3. CO 相关命令 → 校验 confirm_token 是否有效（前端须先获取）
4. 生成唯一 msg_id（格式 pc-cmd-NNNNNN）
5. 通过 HostComm 客户端发送 command 帧，等待 command_result（超时 3s）
6. 将操作记录写入 operator_action 表
7. 返回结果给前端
```

## 4. WebSocket 实时推送协议（后端 ↔ 前端）

端点：`ws://localhost:8000/ws/realtime`  
连接时须携带 `?token=<JWT>` 或首帧携带认证消息（二选一，实现时选一种）。

### 4.1 消息方向：后端 → 前端（推送）

所有推送消息格式：

```json
{
  "type": "<消息类型>",
  "ts": "2026-06-09T10:00:00+08:00",
  "data": { ... }
}
```

| type | 触发时机 | data 说明 |
|---|---|---|
| `status_update` | STM32 推送或轮询刷新（≤1s） | 完整状态快照（同 REST /api/status 的 data 结构）|
| `alarm_new` | 收到 STM32 event（新报警）| `{alarm_id, alarm_code, level, text, occur_time}` |
| `alarm_clear` | 收到 STM32 event（报警消除）| `{alarm_id, alarm_code, clear_time}` |
| `alarm_ack` | 报警被确认后 | `{alarm_id, ack_operator, ack_time}` |
| `state_change` | 状态机切换 | `{from_state, to_state, reason, ts}` |
| `command_result` | 命令执行完成 | `{msg_id, result, reason_code, current_state}` |
| `comm_status` | HostComm 连接状态变化 | `{status: "online"/"offline"/"degraded", ts}` |
| `log_export_progress` | 日志导出进度 | `{task_id, pct, chunks_done, total_chunks}` |
| `report_progress` | 报告生成进度 | `{task_id, step, pct, message}` |

### 4.2 消息方向：前端 → 后端（前端可发）

```json
{"type": "ping"}          // 心跳（服务端回 {"type":"pong"}）
{"type": "subscribe", "topics": ["status", "alarms"]}  // 订阅（默认全订阅）
```

### 4.3 前端 WebSocket 管理（`useWebSocket.js`）

```javascript
// 要求：
// - 自动重连（指数退避，最大 30s）
// - 重连成功后自动重新订阅
// - 连接状态响应式暴露给全局状态（device store）
// - 消息按 type 分发到对应 store 的 action
```

## 5. HostComm 适配器设计（后端 ↔ STM32）

完整协议规格见 `熔滴炉上位机HostComm接口需求清单_V0.2_综合版.html`。  
以下为后端适配器实现规格。

### 5.1 核心组件

```
hostcomm/
  client.py       ← HostCommClient：asyncio TCP 连接生命周期
  protocol.py     ← FrameParser：字节流 → JSON 帧，JSON 帧 → 字节流
  dispatcher.py   ← MessageDispatcher：按 type 路由到各 handler
  heartbeat.py    ← HeartbeatTask：2s 心跳，3次超时告警
  reconnect.py    ← ReconnectTask：指数退避重连（1s → 2s → 4s → 8s → 30s 上限）
  mock_server.py  ← MockHostCommServer：测试用 Mock TCP Server
```

### 5.2 FrameParser（`protocol.py`）

```python
class FrameParser:
    """
    维护字节缓冲区，按 \n 分割 JSON 帧。
    容错：JSON 解析失败时记录日志，继续处理后续帧，不 crash。
    帧大小限制：超过 8192 bytes 的帧丢弃并记录告警。
    """
    def feed(self, data: bytes) -> list[dict]:
        """输入原始字节，返回本次可解析的完整帧列表"""
        ...

    def encode(self, msg: dict) -> bytes:
        """将消息 dict 编码为 UTF-8 JSON + \n"""
        ...
```

### 5.3 HostCommClient（`client.py`）

```python
class HostCommClient:
    """
    asyncio TCP 长连接客户端。
    
    公共接口：
      async def send_command(cmd, params, operator_id, role) -> dict
          发送 command 帧，等待 command_result，超时 3s 抛出 HostCommTimeoutError
      
      async def get_status() -> dict
          发送 get_status，等待 status_snapshot，超时 3s
      
      async def get_parameters() -> dict
          发送 get_parameters，等待 parameters_snapshot，超时 3s
      
      async def request_log_export(test_id, log_types, from_ts, to_ts) -> AsyncIterator[dict]
          发送 log_request，yield log_chunk，直到 log_result
      
      @property
      def is_online(self) -> bool
      
      @property  
      def comm_quality(self) -> str  # "online" / "degraded" / "offline"
    
    内部机制：
      - msg_id 生成：pc-{uuid4_short}（全局递增）
      - 待响应请求用 dict[msg_id → asyncio.Future] 跟踪
      - 收到帧后 dispatcher 按 type 处理：
          status_snapshot → 更新 cache，广播 WebSocket status_update
          event           → 写 event_log，写 alarm_log，广播 WebSocket alarm_new/alarm_clear
          command_result  → resolve 对应 msg_id 的 Future
          heartbeat_ack   → 更新心跳时间戳
          error           → 记录，若 Fatal 则标记 degraded
    """
```

### 5.4 命令幂等性

`send_command()` 在内部维护 `Set[msg_id]` 已发送集合（会话内）。  
如果上层因网络抖动重试，应生成新的 msg_id（不复用），由 STM32 侧保证 msg_id 去重。  
后端 `command_service.py` 负责在重试时生成新 msg_id，并在 `operator_action` 中记录原始和重试记录。

### 5.5 状态缓存（`cache.py`）

```python
class StatusCache:
    """
    线程/协程安全的内存状态缓存。
    
    - 存储最新一次 status_snapshot 的完整 payload
    - asyncio.Lock 保护写操作
    - 提供 get_snapshot() → dict 和 get_field(path: str) → Any
    - 缓存条目含 last_update 时间戳，超过 5s 未更新则 comm_quality = degraded
    """
```

## 6. 认证与权限模型

### 6.1 JWT 实现要点

- 密钥：`SMD_JWT_SECRET`（首次启动自动生成，存入 .env，**不提交**）
- 算法：HS256
- Payload：`{sub: username, role: role, exp: timestamp}`
- 过期：`SMD_JWT_EXPIRE_MINUTES`（默认 480 分钟 = 8小时）
- 本地工控机场景：不需要 refresh token，过期后重新登录

### 6.2 权限矩阵（命令级）

### 6.3 二次确认机制

CO 相关操作（当前：start_test、stop_test 在 CO 工艺阶段）须二次确认：

```
1. 前端显示确认对话框（含 CO 安全警告文本）
2. 用户点击确认后，前端 POST /api/commands/confirm-intent → 后端返回 confirm_token（UUID，有效期 60s）
3. 前端携带 confirm_token 发送实际命令
4. 后端校验 confirm_token 有效 → 继续，否则 403
5. confirm_token 单次使用，使用后立即失效
```

## 8. Mock Server 规格（`hostcomm/mock_server.py`）

开发和 D3 联调早期须在无真实控制板情况下工作。Mock Server 实现一个轻量 TCP Server 模拟 STM32 HostComm 行为。

### 8.1 功能要求

1. 监听本地 `127.0.0.1:34211`（默认）
2. 支持完整 hello/heartbeat/status_snapshot/command_result/event 推送流程
3. 状态机模拟：接受 start_test 后按预设序列自动推进状态
4. 可配置响应行为（通过启动参数或配置文件）：
   - 正常响应模式（accepted）
   - 拒绝模式（rejected + reason_code）
   - 超时模式（不响应）
   - 异常注入：错误 JSON、断线
5. 定期推送模拟状态快照（1s 间隔），数据有合理波动（伪随机）
6. 触发报警：可通过信号或配置在任意时刻注入报警事件
7. **不提供任何绕过安全回路的接口**

### 8.2 启动方式

```bash
# 正常模式（开发用）
python -m app.hostcomm.mock_server

# 注入断线故障（10s 后断线）
python -m app.hostcomm.mock_server --fault disconnect_after=10s

# 全部命令返回 rejected
python -m app.hostcomm.mock_server --mode reject_all
```
