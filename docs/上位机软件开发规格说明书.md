维护角色：软件负责人。2026-09-07当前候选版本为 `0.3.0-rc.4`；`dev@855c84d` 是整改前审查基线。[rc.2记录](verification/2026-09-06-software.md)保留历史范围，当前2.0实现见[运行与配对](hostcomm/v2/runtime.md)、[软件验证](verification/2026-09-06-hostcomm-v2-runtime.md)。真实固件尚未开发；用户已确认一次安装成功，Windows通信/完整实验仍待验。固件交接与主机实现限制见[doc.2交接](hostcomm/v2/firmware-handoff.md)、[兼容表](hostcomm/v2/compatibility.md)。

## 1. 运行边界

Windows桌面与本机/LAN浏览器复用 Vue 前端、FastAPI API、SQLAlchemy/SQLite 和一个 HostComm 网关。STM32 工控板通过网络连接后台，再连接仪表、传感器、天平和 MFC；板端执行实时工艺、温控、配气及安全策略，硬接线联锁保留最终切断权。上位机不增加直接 I/O 或绕过联锁接口。

后台作为独立受限 Windows Service 运行，pywebview 固定 WebView2 薄壳只打开共享界面。关闭窗口/退出登录不结束后台采集。系统单实例和单 Uvicorn worker 防止多窗口产生多个网关；本机默认监听回环，LAN 启用要求 TLS。版本目录、数据目录、升级事务与真实平台验证边界见[发布指南](发布与维护指南.md)。

HTTP/WS 入口调用应用服务；操作/参数/配方服务共享维护和命令门控。状态规范入口为 `status_cache.current_state`，优先读取 state_machine.current_state；双字段冲突返回未知，未知/过期状态不作为启动和改参许可。慢 WS 与数据库写入通过有界队列隔离，不占用 TCP 回执处理路径；丢弃或持久化失败必须显式报告。

## 2. 数据与生命周期

数据结构以 [ORM](../backend/app/db/models.py)、[操作模型](../backend/app/db/operation_models.py)、[配方模型](../backend/app/db/recipe_models.py)和 [Alembic](../backend/app/db/migrations/) 为准。业务 UTC 时间继续遵循 ADR-002；原始采样另存设备时间、接收时间、源序号/boot_id、质量和缺口证据。

TestSession 持久化 phase、stop_requested_at、measurement_completed_at、safety_completed_at、end_time/end_reason、mode、data_integrity、recipe_snapshot_json 和 measurement_basis_json。启动实际参数/配方、样品与报告上下文在发送命令前归档；停止受理后继续记录测定及冷却，身份缺失/不匹配的旧会话保留 needs_review。指标窗口和全流程归档分开；具体质量术语见[扩展契约](hostcomm-experiment-extensions.md)。

原始采样/事件追加保存。报警确认与样品补录属于可修改的业务元数据，必须保留审计。报告重新生成使用新文件，不能覆盖旧结果；历史数据不足时输出未知/限制，不能从全局最新参数补造实验依据。上述[1.0扩展契约](hostcomm-experiment-extensions.md)中的sample id边界及能力字段仅用于兼容分支；2.0按原始boot_id/sample_seq边界、质量和源日志证据归档，见[数据契约](hostcomm/v2/data-and-recipe.md)。

## 3. REST 契约与权限

运行构建的 `/openapi.json` 是类型来源（生产默认关闭文档入口）。前端生成文件由 `npm run api:schema`、`npm run types:generate` 更新，`types:check` 和 `typecheck` 校验。成功通常为 `{data,ts}`。应用业务错误按 HTTP 状态返回顶层 `error_code`、`message`，可附 `ts`、`operation_id`；不能把路由抛出的 `HTTPException.detail` 当作最终响应的嵌套层。应用的422输入校验错误也经统一处理，使用顶层 `validation_error` 错误码，`message` 是面向操作员的固定提示；脱敏后的逐字段条目放在 `detail` 数组中，沿用 OpenAPI 声明的 `ValidationError` 形状（`loc`、`msg`、`type`），不带 `input`、`ctx`，不回显原始输入。

框架原生 HTTP 错误仍可能返回 `{detail: ...}`；前端[公共错误解析器](../frontend/src/api/errors.js)兼容顶层业务错误，以及 detail 中的字符串、对象或错误数组。精确响应以对应构建的[异常处理器](../backend/app/main.py)和契约测试为准，不能据默认 OpenAPI 的422描述推定运行时仍返回原始输入错误数组。

角色按服务端定义分级，Observer只读，Operator可申请受控操作，Admin/Maintainer拥有相应配置与管理权限；高角色不绕过设备状态、控制权或维护锁。下表“Admin+”以实际 `require_role("admin")` 规则为准。

协议由后台显式选择，不在连接失败时自动降级。1.0保留通用参数/CRC路径；2.0的工程profile只读，参数页不提供任意写入，保存的配方经能力和安全校验、分块上传、摘要校验、原子激活及逐字节回读后才能启用。REST业务操作状态与2.0板端wire_status分开记录，applied也不代表实验测定或安全处置已经完成。

| API | 请求和当前行为 |
|---|---|
| `POST /api/auth/login` | 返回token、角色、must_change_password和到期时间；受限账户必须先改密 |
| `GET /api/status` | 缓存快照、后台状态策略、comm_quality、last_update、data_persistence；HTTP查询不直接轮询板端 |
| `POST /api/commands/confirm-intent` | Operator+，CO相关命令一次性二次确认，60秒有效 |
| `POST /api/commands` | command、params、可选confirm_token、operation_id；也支持Idempotency-Key请求头，两处不一致拒绝 |
| `GET /api/commands/operations` | page/size；本人操作，Admin+可查询全部 |
| `GET /api/commands/operations/{operation_id}` | 本人或Admin+，只读持久结果，查询不会重发命令 |
| `POST /api/commands/operations/{operation_id}/query` | 2.0查询板端持久结果；不会重发原操作，含前置租约结果 |
| `POST /api/commands/operations/{operation_id}/reconcile` | 2.0维护核查，须提供reason并通过后台安全条件；未知结果保持未知，记录核查依据 |
| `GET /api/parameters` | 1.0为设备参数及CRC；2.0另返回只读safety_profile、wire_recipe及执行摘要；离线未知值不解释为零 |
| `PUT /api/parameters` | 1.0通用参数入口：values、可选param_crc/operation_id；2.0不开放任意工程参数写入，配方使用受控activate入口 |
| `GET /api/parameters/history` | 分页归档；回读未一致时不保存成功快照 |
| `GET /api/control` | Operator+，返回username、changed_at |
| `POST /api/control/claim` | takeover默认false、reason；已有其他持有人时管理员需提供接管原因并留审计 |
| `DELETE /api/control` | 仅在在线、新鲜、明确空闲且无未闭合实验时释放 |
| `GET /api/recipes/template/standard` | 返回definition、executable:false、requires_device_validation:true；模板不是已部署流程 |
| `GET/POST /api/recipes` | 分页最新配方/保存新配方（Admin+），POST body为definition |
| `GET/PUT /api/recipes/{recipe_id}` | 获取指定version或最新/追加不可变新版本（Admin+） |
| `GET /api/recipes/{recipe_id}/versions` | 历史版本列表 |
| `POST /api/recipes/{recipe_id}/validate` | body为version；返回executable、errors、deviations、安全规则依据 |
| `POST /api/recipes/{recipe_id}/activate` | Admin+，version及可选operation_id；1.0参数CRC/回读，2.0分块暂存、摘要校验、原子激活与原字节回读 |
| `PATCH /api/tests/{test_id}/metadata` | Operator+，sample_metadata/report_context及必填reason；补录保留前后值和操作者 |
| `POST /api/tests/{test_id}/review-close` | Admin+，reason与physical_safety_confirmed；现场确认及有效在线空闲/料温<200后归档为不完整 |
| `POST /api/analytics/repeatability` | Observer+，body为按实际次序的test_ids列表（2—4次）；详见下节 |
| `GET /api/system/maintenance` | Admin+查询版本与维护状态；不暴露本机授权或秘密字段 |
| `POST /api/system/maintenance/prepare` / `DELETE /api/system/maintenance` / `POST /api/system/maintenance/claim` | 0.3.0退役，返回明确的安装器指引；不再由页面生成/领取维护许可 |
| `POST /api/system/maintenance/source-logs` | Admin+，2.0在线设备源日志补传；可选first_record_seq为uint64十进制字符串，返回后台task_id |
| `GET /api/system/maintenance/source-logs/{task_id}` | 查询日志补传任务；completed不自动证明实验数据完整 |
| `/api/tests`、`/api/trends`、`/api/alarms`、`/api/reports` | 历史、曲线、报警和三格式报告；动词/分页/输入以OpenAPI为准 |
| `GET /health` / `GET /api/system/health` | 进程存活/应用就绪；设备离线不单独否定历史查询服务 |

HTTP持久操作状态为 pending、sent、accepted、verified、rejected、unknown。accepted仅表示受理，verified表示回读验证完成；两者都不是实验测定完成。重试同operation_id、同操作者和同参数只返回原记录；更换参数/操作者拒绝409。后台启动将无最终记录的中断操作标unknown，不自动重发有副作用命令。2.0的持久身份、高水位、结果查询和防重放已有上位机/模拟器回归，真实板端保证仍待固件实现。精确查询与核查语义见[命令路由](../backend/app/api/routes/commands.py)、[操作核查说明](hostcomm/v2/runtime.md#5-操作核查与源日志恢复)。

控制权存数据库、各客户端共享；首次有效操作自动取得控制权，管理员接管需原因。stop_test不被控制权持有人阻止，但仍经过角色、状态、二次确认与审计。维护状态阻断命令/参数变更；升级权限由 Windows 安装器的本机受保护请求、后台在普通/优先两条命令锁内的状态判定，以及服务/进程实际退出共同构成。已知运行或冷却拒绝；已配对但离线或状态未知时，管理员须在安装器确认现场已安全停机。未完成实验、源日志缺口和未知操作保持原记录，不能因更新补写安全终态。旧版本使用专用兼容维护路径，不伪造JWT/旧claim请求，详见[ADR-011](decisions/ADR-011-overwrite-install-and-software-release.md)和[发布指南](发布与维护指南.md#4-人工离线升级和恢复)。离线配对仍有独立停机和数据库证据检查。

## 4. 样品、报告补录与重复性

启动params包含 test_id、original_height_mm、可选sample_label/notes；1.0具备recipe_v1时以及2.0启动时，必须给recipe_id与recipe_version。可附sample_metadata、report_context；它们保存在上位机，不发送给板端。原始高度输入范围0<H≤10000mm是输入保护，不是国标合格范围。

sample_metadata字段：batch、preparation、particle_min_mm/particle_max_mm、dry_temperature_c、dry_duration_min、sample_mass_g、coke_upper_g/coke_lower_g、h1_mm/h2_mm、load_kg_cm2、sealed_leak_pressure_pa、loaded_pressure_pa、leak_n2_l_min、preparation_confirmed、remarks。量值有限且满足结构边界；H=H1−H2须正值且与已记录高度一致。元数据录入不自动证明粒级、干燥或加载符合国标。

report_context字段：laboratory_name、laboratory_address、test_date、abnormal_operations、additional_operations。补录reason用于METADATA_REVISED事件，记录旧值、新值、操作者和高度变化；不静默覆盖损坏依据或冲突高度。管理员核查关闭记INCOMPLETE_ARCHIVED事件、manual_review_incomplete原因、archived_incomplete阶段和incomplete完整性，不能用于有效重复性判定。

repeatability响应包括eligible、errors、test_ids、results、standard。所有输入必须存在、不重复、同sample_metadata.batch、同mode和同recipe摘要；每次已经闭合、measurement_completed_at存在、data_integrity=complete。四指标必须有有效值，否则返回eligible:false和错误，results为空。eligible表示输入可判定，**不等于附录B已经无需补试**；各指标结果另外返回metric、values、result、additional_runs、used_values、tolerances和rules_version。按请求次序使用2/3/4次值，不重排试验；A/B/C和最终修约见[实验规范](experiment-spec.md)。

## 5. WebSocket

端点 `/ws/realtime`；首帧 `{"type":"authenticate","token":"JWT"}`，成功返回auth_ok。随后ping得到pong，服务端复核会话；JWT不放URL。没有subscribe/unsubscribe接口，其他客户端消息返回unsupported_message。

认证/重连后发送当前状态和活跃报警快照，后续推送状态/事件/报警。连接有Origin、大小、频率、空闲和每用户数量限制。浏览器→后台与后台→STM32两条链路分别显示，过期数值不作为实时许可。具体消息以 [WebSocket](../backend/app/api/websocket.py)、[推送管理](../backend/app/api/ws_manager.py)与 [应用回调](../backend/app/main.py) 为准；2.0已实现源日志补传且不回退实时状态，真实设备端日志与缺口恢复仍待固件实现和联调。
