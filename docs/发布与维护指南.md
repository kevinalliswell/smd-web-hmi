# 发布与维护指南

## 1. 分支策略

- `main` 是正式稳定线，本轮商用收口不直接修改。
- `dev` 是当前过渡集成线；功能/修复分支通过 PR 合入 `dev`。
- 候选分支为 `release/commercial-readiness`；CI 全绿后合入 `dev`。
- 真机 D4 签字前不创建正式 tag；签字后再决定 `dev → main` 的发布 PR。
- 合并使用 squash 或保持语义清晰的阶段提交；禁止绕过 CI。

GitHub 分支保护至少要求：PR、线性历史和以下 checks：Black/isort、Linux Python 3.11/3.12、
Windows Python 3.11、前端测试/构建、依赖审计。仓库当前尚未启用保护时，负责人需在网页端补设。

## 2. 版本

- 后端权威版本：`backend/app/__init__.py`。
- 前端 `package.json` 与候选版同步，帮助页直接展示。
- 当前候选：`0.3.0-rc.1`；真机通过后发布 `0.3.0`。
- 已发布 Alembic migration 只追加，不修改历史文件；升级说明必须注明 head revision。

## 3. CI / 本地门禁

```bash
cd backend
python -m pytest -q --cov=app --cov-report=term --cov-fail-under=80
python -m black --check app tests
python -m isort --check-only app tests

cd ../frontend
npm ci
npm run lint
npm run test
npm run build
```

依赖审计：

```bash
pipx run pip-audit -r backend/requirements.lock
cd frontend && npm audit --audit-level=high
```

依赖输入文件变化后，用 `uv pip compile --universal --generate-hashes --strip-extras` 同步运行/开发锁文件；
离线安装始终使用 `--require-hashes --no-index --find-links=wheels`。

## 4. 候选包与正式发布

1. 在 Actions 手工运行 Release workflow，version 填 `v0.3.0-rc.1`；这只生成 artifact，不创建 Release。
2. 下载 zip 与 SHA256，按 `deploy/windows/README.md` 在干净 Windows 机演练。
3. 完成 `docs/D4-readiness.md` 的现场清单并回填供应商冻结表。
4. 将版本改为 `0.3.0`、更新 CHANGELOG、走正式发布 PR。
5. 打 annotated tag `v0.3.0`；Release workflow 重新测试、构建 Windows wheels、校验包结构并创建 Release。
6. 交付 zip、SHA256、固件兼容矩阵和签字记录。

## 5. 生产启动与健康

- 生产必须设置 `SMD_JWT_SECRET`、`SMD_BOOTSTRAP_ADMIN_PASSWORD_FILE`（仅首次建 admin 时读取）和真实 HostComm 地址。
- `install.bat` 以管理员权限离线安装依赖、收紧密钥/数据 ACL、执行 `alembic upgrade head`，再注册并启动 SYSTEM 计划任务。
- 服务由 `python -m app.server` 启动并读取 `.env` 的 host/port；生产访问日志关闭，应用日志为 JSON。
- `/health` 是进程存活；`/api/system/health` 检查 schema、存储、备份和 HostComm。
- `health_check.ps1` 用于交付验收和巡检；服务日志在 `logs/server.log`。

## 6. 数据保护、升级与回滚

- 生产按 `SMD_BACKUP_INTERVAL_HOURS` 使用 SQLite online backup API；每个备份执行 `PRAGMA integrity_check`。
- 默认备份保留 30 天，临时导出保留 7 天；报告和业务日志不自动删除。
- 管理员可调用 `POST /api/system/backup` 立即备份；系统设置页可查看最后备份状态。
- 升级脚本主动撤销自动重启任务，以同一 SQLite backup API 创建升级前备份，并保留 `.env` 与旧程序；失败时自动恢复数据库和程序。
- 回滚使用旧程序 + 升级前整库备份，不使用 `alembic downgrade`；回滚会丢失升级后数据，必须先留档。

## 7. 事件处置

- readiness schema=outdated：停止服务，在 `app/backend` 执行 `venv\Scripts\python -m alembic upgrade head`。
- backup=error：检查数据盘空间/权限，执行管理员手工备份并查看 JSON 日志中的 request_id。
- storage free 不达门槛：清理过期导出/旧备份或扩容；不得删除业务数据库、报告或只追加日志表。
- HostComm offline：服务本身仍可读取历史；按 IP/端口、网线、固件状态和 Mock `disconnect_after` 演练路径排查。
- 会话异常：角色/密码变更会使旧 token 立即失效；重新登录，不得恢复或复用旧 token。
