## 2. 共用检查和产物

[PR CI](../.github/workflows/ci.yml)和[tag发布](../.github/workflows/release.yml)均调用[Shared checks](../.github/workflows/checks.yml)。目标Node24、Python3.13；CI保留LinuxPython3.11兼容检查，但桌面发行运行时固定Python3.13。

必要检查包括文档链接、Black/isort、版本与锁一致性、先行安全红线测试、空数据库迁移、后端全套及覆盖率≥80%、桌面事务/进程测试、前端OpenAPI漂移与类型、lint/测试/build、运行依赖审计。Windows job还解析PowerShell并构建冻结服务、桌面壳、更新器及NSIS；原安装冒烟清理后，独立SmdBench再执行自己的新装、配对、TLS/页面/报告/故障流程并清理。**工作流已配置不等于该轮Windows job已通过**，结果需绑定最终SHA和CI链接。

实际构建入口为 [scripts/release/build-windows.ps1](../scripts/release/build-windows.ps1)，打包定义位于 [desktop](../desktop/)。旧源码+wheels和计划任务安装/升级脚本已移除，不再作为执行入口。Windows产物为SmdHmi-版本-windows-x64.exe、manifest.json、sbom.cdx.json、SHA256SUMS.txt，以及独立SmdBench-版本-windows-x64.zip、bench-manifest.json和bench-acceptance.json。工具清单记录Chromium/Python/场景版本和逐文件校验值；验收记录同时绑定安装器和工具清单的实际字节，不能复用同提交的其他构建结果。tag检查全部通过后，[发布门禁](../scripts/release/publish_gate.py)在发布前再次核对下载清单的version、commit与真实布尔prerelease字段；当前只接受`vX.Y.Z-rc.N`（N为正整数），并固定标记prerelease。正式版本一律拒绝：M5尚未接入可核验的正式资格证据，清单中的firmware_validation/windows_validation说明文字、非空字符串、`passed`或`true`均不能解锁。M5须通过独立评审引入绑定软件/固件/Windows组合与产物的验收契约，再修改门禁；本轮不添加可冒充验收的标记文件。workflow_dispatch只构建、不自行发布新tag。

[版本元数据检查](../scripts/release/metadata.py)检查版本匹配；[锁检查](../scripts/release/check_locks.py)发现声明/锁和共享依赖不一致。包清单包含版本、提交、schema、组件和文件hash。hash证明文件完整性，不能替代可信分发和正式签名。

## 3. 双端与固定运行时

Win10/11 x64使用pywebview+固定WebView2、PyInstaller onedir和NSIS。每个版本保留独立SmdService、SmdDesktop、SmdUpdate冻结程序及私有依赖、frontend和webview2目录。安装后不依赖现场Python/Node。NSIS仍检查Windows/.NET等平台前提；干净断网机器必须实测全部前提，不允许通过联网自动补依赖伪称离线包。

固定WebView2版本、官方来源和SHA-256由[webview2.lock.json](../desktop/webview2.lock.json)维护；构建校验归档hash、Microsoft签名和产品版本，运行时缺失或不匹配必须失败。不能用空runtime目录产出假离线安装器。安全更新随新离线包发布，保留旧版本以供事务回退。

程序存ProgramFiles/SmdHmi/versions，配置、数据库、日志、升级日志和票据存ProgramData/SmdHmi。后台Windows服务SmdHmi使用LocalService与服务SID，系统级互斥及单worker保证唯一后台；普通桌面进程关闭不停止服务。SYSTEM启动恢复任务只处理升级恢复，不能把日常采集重新提升为SYSTEM。卸载保留ProgramData，运行状态必须通过维护许可。

源码 Web 入口使用 `python -m app.server`，从 `backend/.env` 读取监听与 TLS 证书路径；默认只监听回环。所有生产入口在恢复数据或连接 STM32 前取得同机设备租约，生产 HOSTCOMM_HOST 使用字面 IP。POSIX 需管理员预建共享锁目录，Windows 使用跨账户 Global mutex；准备方式与跨主机边界见 [ADR-007](decisions/ADR-007-device-gateway-lease.md)。

回环默认127.0.0.1:8000；LAN监听必须配置TLS证书/私钥并建立客户端信任，桌面不关闭证书校验。现场防火墙、证书生命周期和正式签名见Q14。私钥、JWT密钥与一次性口令存受保护目录，不能随源码或公开包分发。

## 4. 人工离线升级和恢复

rc.3覆盖升级失败的现场日志已确认缺少 `C:\ProgramData\SmdHmi\maintenance.json`。应先在旧软件“系统设置 → 离线升级”为精确目标版本准备维护，再运行安装器；rc.4改善提示和日志定位，不自动生成或绕过许可。尚未验证用户现场重试成功；旧1.0后台的在线维护条件不会被新安装包反向改变，详见[排查记录](verification/2026-09-06-windows-installer-errors.md)。

已有实验须先完成安全处置及结束确认，管理员在界面准备目标版本维护；安装器读取本机受保护票据。prepare和claim两次执行[维护就绪检查](../backend/app/api/routes/maintenance.py)，确认所有TestSession.end_time非空，包括needs_review。HostComm 2.0 还拒绝未核查的在途或未知设备操作：明确未配对的新安装无需连接设备即可维护；已配对安装必须在线重新读取状态，确认run.state为idle且run_id为空，completed尚未确认结束不能放行。1.0兼容入口仍要求在线、新鲜且明确空闲。prepare票据有限期，claimed状态不能由网页取消；同一维护门控阻断控制和参数变更。

升级核心按持久事务执行：

1. 验证平台、版本、文件hash和来源，完整暂存新版本程序/运行时。
2. 领取维护许可、记录旧/新版本与阶段；确认SCM服务真正停止，超时不能继续覆盖数据库。
3. 从实际service.env解析SMD_DB_PATH，用SQLite在线备份和完整性校验保存数据库，同时保存配置、版本指针、服务与恢复任务配置。自定义数据库路径不得退回硬编码默认路径。
4. 用新冻结服务执行迁移，切换服务版本和指针，在有界时间内验活版本、schema、可写存储、备份状态和前端入口。
5. 成功才提交日志并释放维护锁；任何失败恢复旧程序、依赖、配置、数据库、SCM和恢复任务，再验活。恢复失败保留维护阻断与错误证据。

日志标记prepared/stopped/migrating/starting/committed及回滚阶段；重启按日志幂等恢复，使用持久写入避免仅凭目录推测成功。旧终态日志不得清除后来新创建的维护票据。

事务中失败回退不同于新版本已运行一段时间后降级：后者必须先保存新实验并评估schema兼容，不能用升级前备份直接覆盖后续数据。没有经过验证的Alembic downgrade替代方案。设备离线不阻止首次安装或历史读取；未配对的2.0安装可按上述条件升级，已配对设备离线则不能领取升级许可，二者均不能离线控制。设备配对、更换密钥及其中断恢复使用[独立配对事务](hostcomm/v2/runtime.md#4-中断恢复与版本升级)，不能与软件升级恢复入口混用。

## 5. 分层证据和现场发布门

软件已覆盖升级核心故障注入、备份实际路径、维护互斥、断电日志恢复等可测试路径。rc.2 的 Windows CI 实际运行和构建范围见[历史软件验证](verification/2026-09-06-software.md#最终集成软件验证)，rc.3 功能增量见[运行验证](verification/2026-09-06-hostcomm-v2-runtime.md)，rc.4 安装诊断增量见[排查记录](verification/2026-09-06-windows-installer-errors.md)；新候选包仍须绑定其最终提交的检查和资产。不能由构建通过推定NSIS交互安装、LocalService现场权限、系统重启、干净断网或真实断电已验收。M4现场和M5仍须提供Windows10/11主机、固件/仪表/MFC组合、签名和证书信任、完整实验及24h记录。
