# 发布与维护指南

维护角色：发布负责人。2026-09-06更新；当前候选版本为 `0.3.0-rc.2`。桌面/服务/安装器和事务升级代码已实现；WindowsCI初轮发现问题后已修复重跑，正在等待运行结果，干净断网现场与M5未验收。操作细节见[Windows交付说明](../deploy/windows/README.md)，决策见[ADR-005](decisions/ADR-005-shared-runtime-and-evidence.md)。

## 1. 分支和版本

main是唯一长期分支；短期分支经PR和必要检查后squash合入。此次PR48保留dev@855c84d祖先关系、PR64整合M0文档，属于[ADR-003](decisions/ADR-003-project-baseline.md)的一次性整合。全引用bundle与恢复验证已完成；剩余分支清理由根任务核对有效改动、PR及引用后处理，不把新Dependabot工作当作旧残留删除。

版本真源为backend/app/__init__.py的__version__；frontend/package.json、lock、manifest与tag必须一致。沿用候选序列，本轮推进到rc.2以识别旧页面/新后台，不自动创建发布tag；正式版本前使用RC，tag前缀v，已发布标签不移动。CHANGELOG的Unreleased记录本轮增量，发行时绑定最终提交与证据。

GitHub保护能力取决于账户套餐/权限。只记录实际启用规则，不能将约定的PR流程写成平台已强制。保留有用依赖升级PR；patch/minor按生态分组且限制未完成数量，主版本单独评估。依赖声明和hash锁必须同步，不能用只改txt的PR绕开锁文件校验。

## 2. 共用检查和产物

[PR CI](../.github/workflows/ci.yml)和[tag发布](../.github/workflows/release.yml)均调用[Shared checks](../.github/workflows/checks.yml)。目标Node24、Python3.13；CI保留LinuxPython3.11兼容检查，但桌面发行运行时固定Python3.13。

必要检查包括文档链接、Black/isort、版本与锁一致性、先行安全红线测试、空数据库迁移、后端全套及覆盖率≥80%、桌面事务/进程测试、前端OpenAPI漂移与类型、lint/测试/build、运行依赖审计。Windows job还解析PowerShell并构建冻结服务、桌面壳、更新器及NSIS。**工作流已配置不等于该轮Windows job已通过**，结果需绑定最终SHA和CI链接。

实际构建入口为 [scripts/release/build-windows.ps1](../scripts/release/build-windows.ps1)，打包定义位于 [desktop](../desktop/)。旧源码+wheels和计划任务安装/升级脚本已移除，不再作为执行入口。Windows产物为SmdHmi-版本-windows-x64.exe、manifest.json、sbom.cdx.json、SHA256SUMS.txt。tag检查全部通过后发布同一批产物，含连字符的候选tag标记prerelease；workflow_dispatch只构建、不自行发布新tag。

[版本元数据检查](../scripts/release/metadata.py)检查版本匹配；[锁检查](../scripts/release/check_locks.py)发现声明/锁和共享依赖不一致。包清单包含版本、提交、schema、组件和文件hash。hash证明文件完整性，不能替代可信分发和正式签名。

## 3. 双端与固定运行时

Win10/11 x64使用pywebview+固定WebView2、PyInstaller onedir和NSIS。每个版本保留独立SmdService、SmdDesktop、SmdUpdate冻结程序及私有依赖、frontend和webview2目录。安装后不依赖现场Python/Node。NSIS仍检查Windows/.NET等平台前提；干净断网机器必须实测全部前提，不允许通过联网自动补依赖伪称离线包。

固定WebView2版本、官方来源和SHA-256由[webview2.lock.json](../desktop/webview2.lock.json)维护；构建校验归档hash、Microsoft签名和产品版本，运行时缺失或不匹配必须失败。不能用空runtime目录产出假离线安装器。安全更新随新离线包发布，保留旧版本以供事务回退。

程序存ProgramFiles/SmdHmi/versions，配置、数据库、日志、升级日志和票据存ProgramData/SmdHmi。后台Windows服务SmdHmi使用LocalService与服务SID，系统级互斥及单worker保证唯一后台；普通桌面进程关闭不停止服务。SYSTEM启动恢复任务只处理升级恢复，不能把日常采集重新提升为SYSTEM。卸载保留ProgramData，运行状态必须通过维护许可。

回环默认127.0.0.1:8000；LAN监听必须配置TLS证书/私钥并建立客户端信任，桌面不关闭证书校验。现场防火墙、证书生命周期和正式签名见Q14。私钥、JWT密钥与一次性口令存受保护目录，不能随源码或公开包分发。

## 4. 人工离线升级和恢复

操作员先结束并安全关闭实验，管理员在界面准备目标版本维护；安装器读取本机受保护票据。prepare和claim两次校验设备在线、状态新鲜且明确空闲，并确认所有TestSession.end_time非空，包括needs_review。prepare票据有限期，claimed状态不能由网页取消；同一维护门控阻断控制和参数变更。

升级核心按持久事务执行：

1. 验证平台、版本、文件hash和来源，完整暂存新版本程序/运行时。
2. 领取维护许可、记录旧/新版本与阶段；确认SCM服务真正停止，超时不能继续覆盖数据库。
3. 从实际service.env解析SMD_DB_PATH，用SQLite在线备份和完整性校验保存数据库，同时保存配置、版本指针、服务与恢复任务配置。自定义数据库路径不得退回硬编码默认路径。
4. 用新冻结服务执行迁移，切换服务版本和指针，在有界时间内验活版本、schema、可写存储、备份状态和前端入口。
5. 成功才提交日志并释放维护锁；任何失败恢复旧程序、依赖、配置、数据库、SCM和恢复任务，再验活。恢复失败保留维护阻断与错误证据。

日志标记prepared/stopped/migrating/starting/committed及回滚阶段；重启按日志幂等恢复，使用持久写入避免仅凭目录推测成功。旧终态日志不得清除后来新创建的维护票据。

事务中失败回退不同于新版本已运行一段时间后降级：后者必须先保存新实验并评估schema兼容，不能用升级前备份直接覆盖后续数据。没有经过验证的Alembic downgrade替代方案。设备离线不阻止首次安装或历史读取，但阻止需要新鲜设备状态的升级领取和控制请求。
