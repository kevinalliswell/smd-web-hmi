# 发布与维护指南

维护角色：发布负责人。2026-09-13 更新。本轮实施保留数据的覆盖安装，目标为 `0.3.0` 软件正式版；**尚未凭本文认定该版本已发布或验收通过**。实际标签、检查、文件摘要和发布状态以 [GitHub Releases](https://github.com/kevinalliswell/smd-web-hmi/releases) 及其证据为准。决策见 [ADR-011](decisions/ADR-011-overwrite-install-and-software-release.md)，实施进度见[任务清单](../tasks/todo.md)。

rc.4/rc.5 要求旧页面准备维护的行为属于历史版本，见[安装排查记录](verification/2026-09-06-windows-installer-errors.md)。rc.5 的安装版模拟实验验证只适用于[记录中的实际构建](verification/2026-09-08-installed-hostcomm-loop.md)，不能代替本轮旧版升级验收。

## 1. 分支和版本

`main` 是唯一长期分支；短期分支经 PR 和必要检查后 squash 合入。历史整合与可恢复 Git bundle 见[ADR-003](decisions/ADR-003-project-baseline.md)及[仓库整理证据](verification/2026-09-06-software.md#最终集成软件验证)。不重写主线，不移动或替换旧 RC 标签及附件。

[backend/app/__init__.py](../backend/app/__init__.py) 的 `__version__` 是版本真源。前端、lock、包清单和标签必须一致，由[版本检查](../scripts/release/metadata.py)核对。候选版本采用 `X.Y.Z-rc.N`；软件正式版采用 `X.Y.Z`，标签加 `v`。本轮目标 `v0.3.0`，软件正式版的含义是列明软件范围通过验收，不等于真实设备或国标实验已通过。

main 的必要检查、PR、线性历史和已解决讨论规则适用于管理员；`v*` [不可移动规则](https://github.com/kevinalliswell/smd-web-hmi/rules/22343587)禁止更新与删除旧标签。权限规则和版本号都不能代替验收。依赖声明与 hash 锁同步，主版本依赖升级单独验证。

## 2. 共用检查和产物

[PR CI](../.github/workflows/ci.yml) 与 [tag 发布](../.github/workflows/release.yml) 调用同一 [Shared checks](../.github/workflows/checks.yml)。桌面构建使用 Python 3.13、Node 24；后端保留 Linux Python 3.11 兼容检查。文档、Black/isort、版本/锁、先行安全测试、Alembic、后端覆盖率至少 80%、桌面事务、前端契约/类型/lint/测试/build 和依赖审计均为必要检查。

Windows job 必须使用实际安装器、受限服务及 Chromium 页面完成新装、真实 rc.4/rc.5 升级、数据/配置保留、同版本修复、拒绝降级、离线确认、忙碌拒绝、失败事务恢复和自定义数据库验收；随后复用独立 SmdBench 的 TLS、配方、实验、恢复、报告与故障场景。脚本存在或 CI 构建通过，不等于这些行为已经通过。

构建入口为 [build-windows.ps1](../scripts/release/build-windows.ps1)。发行资产包含：

- `SmdHmi-版本-windows-x64.exe`、`manifest.json`、`sbom.cdx.json`、`SHA256SUMS.txt`、更新与升级说明。
- 独立 `SmdBench-版本-windows-x64.zip`、`bench-manifest.json`、`bench-acceptance.json`。
- 软件正式版另含 `software-acceptance.json`、`windows-acceptance.json` 及其引用的脱敏场景日志。

[发布门禁](../scripts/release/publish_gate.py)校验版本、提交与真实布尔 prerelease 字段。RC 保持候选规则；软件正式版必须通过[证据契约](release-acceptance.md)，核对当前 CI 编号、实际安装器/工具 ZIP/清单/日志 SHA-256、完整唯一通过场景和未验收范围。ZIP 内逐文件清单也必须匹配实际验收工具。manifest 中的说明文字或单独 `passed`/`true` 不能解锁。发布时 stable 的 prerelease 为 false；工作流手动构建不自动创建发布标签。

摘要证明字节一致性，不能替代可信分发或正式签名。Q14 的签名、现场证书和信任环境仍独立跟踪。

## 3. 双端与固定运行时

Win10/11 x64 桌面沿用 pywebview、固定 WebView2、PyInstaller onedir 与 NSIS；每版本包含服务、桌面壳、更新器、页面和依赖。现场无需安装 Python 或 Node。Windows/.NET 前提仍须检测；固定运行时缺失或不匹配则构建/启动失败，不临时联网补齐后宣称断网安装已验收。

WebView2 的版本、官方来源和 SHA-256 由 [webview2.lock.json](../desktop/webview2.lock.json)维护；安全更新随离线包分发。程序位于 `Program Files\SmdHmi\versions`，持久配置、数据库、日志和恢复记录默认位于 `ProgramData\SmdHmi`；自定义实际数据库路径继续使用原配置。

服务 `SmdHmi` 使用 LocalService 和服务 SID，系统互斥与单 worker 保证唯一后台。普通用户关闭桌面不会停止服务。SYSTEM 启动恢复任务只处理明确的事务恢复。卸载默认保留数据目录，不能通过“重新安装”静默建立空库。

源码 Web 入口为 `python -m app.server`，默认回环监听。LAN 配置 HTTPS、可信证书和明确访问范围，桌面与页面共用认证及 API。设备网关跨账户互斥见 [ADR-007](decisions/ADR-007-device-gateway-lease.md)。私钥、JWT、PSK 和一次性口令只存受保护目录，不进入公开包或验证日志。

## 4. 人工离线升级和恢复

0.3.0 的正常操作为：**下载新版安装器 → 运行并同意 Windows 提权 → 确认安装 → 完成**。目标版本由包清单读取，不登录旧软件、不手填版本号、不先卸载。已有安装沿用登记路径。设置页的“版本与维护状态”仅查询，不创建或取消维护票据。

设备明确空闲时由安装器继续；明确处于实验、置换或冷却阶段时拒绝，用户应先按实验操作完成处置。已配对设备离线或状态未知时，安装器可要求 Windows 管理员确认设备已在现场安全停机。该确认只授权停机维护，未完成档案和未知命令保持原样，不据此补写安全终态。首次未配对安装无需设备在线。

安装器按持久事务执行：

1. 校验包清单、版本、文件和空间；完整程序仅在安装盘暂存一次，更新器引导程序单独执行。相同版本相同发行清单允许修复，版本复用和普通降级拒绝。
2. 创建绑定操作类型、包摘要、版本、事务和管理员身份的本机受保护请求。新后台在两条命令锁下重新检查并回应；兼容旧版本使用专用路径，不能伪造网页令牌或启动第二个网关。
3. 正常停止服务并确认 SCM 与进程退出，核对持久活动记录和实际数据库路径，再检查所需空间。停止失败不操作数据库。
4. 备份实际数据库和配置，核验完整性后执行 Alembic。既有账户、密码、密钥、网络/配对配置、配方、实验、报告和路径保留；只补缺省配置。
5. 切换程序、服务和版本指针；检查应用版本、数据库/schema/存储/备份及页面入口，通过后提交并释放本事务的维护门控。设备离线不导致应用就绪检查失败。
6. 失败恢复对应程序、配置和数据库。新日志记录已恢复数据、已配置旧版和等待验活等阶段，仅剩验活时不重复恢复数据库。成功后程序保留当前、上一个版本及未完成事务引用；本轮不自动删除数据库/配置备份或原始数据、报告。

遇到旧 `rollback_failed` 时，新安装器先额外保存当前数据库、配置和原日志，说明恢复影响，再尝试一次恢复；成功才继续更新。失败保留证据，不删除维护锁或反复覆盖恢复。旧终态日志不能清除较新的事务。配对、卸载、恢复分别处理，升级不能暗中继续卸载。诊断日志包含 UTC 时间与具体失败检查，但不输出秘密材料。

空间检查按卷计算程序暂存、数据库/配置备份、迁移和恢复临时文件，保留现有存储最低空闲门槛；不会靠降低该门槛掩盖磁盘不足。新版本正常使用后想回到更低版本，不能简单用升级前数据库覆盖新增实验，必须另行评估并保全这些数据。

操作入口与实际参数见 [Windows 交付说明](../deploy/windows/README.md)。历史 rc.4/rc.5 的手动 prepare/claim 和 PowerShell 排查流程只用于对应历史故障分析，不是 0.3.0 正常升级步骤。设备配对仍使用[独立配对事务](hostcomm/v2/runtime.md#4-中断恢复与版本升级)。

## 5. 分层证据和现场发布门

软件正式版门禁覆盖同一构建的必要软件检查、Windows CI 实际安装/升级和安装版 SmdBench。`software-acceptance.json` 固定列出尚未验收的 Win10/11 桌面、固件、物理联锁及国标符合性，不把 Windows Server 的测试环境写成 Win10/11 实机。

Win10/11 干净断网 WebView2、窗口关闭持续采集、普通操作员、中文路径与缩放、证书信任、实际断电和长期运行逐项记录现场结果。M5 另要求目标 STM32、仪表/MFC、安全工程 profile、完整标准/非标实验、最高批准采样率 24 小时及恢复记录。未取得的证据继续标“未验收”，不妨碍列明范围的软件发布，也不构成设备投入运行的资格。

每轮记录提交、实际包摘要、数据库/协议/固件/硬件/运行时组合、环境、步骤、预期与实际、CI/现场来源和责任角色。软件、模拟器、Windows CI、Windows 桌面和真机结果分别记录，格式见[验证规范](verification.md)。
