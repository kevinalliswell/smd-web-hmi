# 发布与维护指南

> 本文是 2026-08-29 全面审查后确立的工程流程基线（对应"工程骨架" PR）。
> 分支模型的权威定义在 `CLAUDE.md` §6，本文展开操作细节。

## 1. 分支与合并（trunk-based）

- **main 是唯一长期分支**，只通过 PR 更新；`fix/xxx`、`feature/xxx` 短命分支从 main 拉出，合并后删除。
- **合并方式一律 squash**：PR 标题写成 Conventional Commits 格式（如 `fix(hostcomm): 心跳超时触发断链重连`），squash 后它就是 main 上的提交信息。
- 一个 PR 对应一个 issue（或 issue 内的一条勾选项），描述里写 `Closes #N` / `Part of #N`；issue 的所有勾选项完成才关闭。
- 每个缺陷修复 PR 必须包含**复现该缺陷的测试**（先红后绿）。

### 分支保护（需在 GitHub 网页手动配置一次）

Settings → Branches → Add protection rule，分支名 `main`：

- ✅ Require a pull request before merging（单人仓库不必勾 required approvals）
- ✅ Require status checks to pass，勾选：`静态检查 (black + isort)`、
  `后端 (ubuntu-latest / py3.11)`、`后端 (windows-latest / py3.11)`、`前端 (vitest + build)`
- ✅ Require linear history（配合 squash 合并）

## 2. 版本管理

- **唯一版本源**：`backend/app/__init__.py` 的 `__version__`（前端经 `/api/system/info` 与 `/health` 展示；`frontend/package.json` 的 version 不再维护语义）。
- **SemVer + 里程碑**：D3 工程基线 `v0.2.x` → 修复迭代递增 patch → D4 冷态验收通过打 `v0.4.0`（tag 注释注明阶段）。
- **数据库 schema 属于版本**：已发布的 Alembic 迁移只追加、永不修改；发版说明注明"需 `alembic upgrade head`"。
- **固件兼容矩阵**：每个 release 注明适配的固件版本/能力集（hello_ack 已采集 `fw_version`）。状态词表冻结进度见 issue #15 第 3 条。

### 发版 SOP

1. 确认 main 全绿、无未闭合的阻断 issue；
2. 改 `backend/app/__init__.py` 的 `__version__`；
3. 更新 `CHANGELOG.md`（把 Unreleased 段落归入新版本号）；
4. 提交合并后打 tag 并推送：

   ```bash
   git tag -a v0.3.0 -m "D3 联调基线"
   git push origin v0.3.0
   ```

5. `release.yml` 自动：跑测试（安全红线优先）→ 构建前端 → 下载 win_amd64 wheels → 组离线包 → 创建 GitHub Release（zip + SHA256SUMS）；
6. 下载 zip，按 `deploy/windows/README.md` 交付现场。

> 试运行：Actions → Release → Run workflow（workflow_dispatch）只构建产物不发 Release，
> 用于在打正式 tag 前验证打包流水线。

## 3. CI 说明（.github/workflows/ci.yml）

| Job | 内容 | 门槛 |
|---|---|---|
| 静态检查 | black / isort / ESLint（配置在 `backend/pyproject.toml`、`frontend/eslint.config.js`） | 必须通过 |
| 后端矩阵 | ubuntu(py3.11/3.12) + **windows(py3.11)**；安全红线最先跑 → alembic → 全量 pytest | 必须通过 |
| 覆盖率 | `--cov-fail-under=70`（防倒退基线） | 必须通过；**D3 目标：核心路径 ≥80%**，随修复 PR 补测试后上调此值 |
| 前端 | ESLint + vitest + build，dist 传 artifact | 必须通过 |
| 依赖审计 | pip-audit + npm audit（high 及以上） | 必须通过 |

本地提交前：`pip install pre-commit && pre-commit install`（black + isort + ESLint 钩子）。
Python 安装统一使用 `pip install --require-hashes -r backend/requirements[-dev].lock`；修改输入文件后用
`uv pip compile --universal --generate-hashes --strip-extras -o backend/requirements.lock backend/requirements.txt`
（开发依赖同理）重新生成锁文件。

## 4. 部署形态与现场运维

- **同源部署**：后端托管 `vite build` 产物（`SMD_FRONTEND_DIST`，源码部署自动探测 `frontend/dist`），单端口 8000，无跨域。
- 离线包结构、首次安装、升级、回滚、开机自启：见 `deploy/windows/README.md`。
- 铁律：`data\smd.db` 与程序目录分离，升级不触碰；升级前自动冷备；回滚整库还原备份而非 `alembic downgrade`（日志表只追加，红线 7）。
